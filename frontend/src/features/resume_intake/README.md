# resume_intake (UI)

The recruiter's interview screen. The interviewer drops in a candidate's CV, fills in the interview form and submits. While the CV is processed a progress card shows the stage, and the page then shows the details AI extracted from the CV, the text read from it, and the submitted answers. The backend half is in `backend/app/features/resume_intake/`, and the designs are `docs/features/resume_intake.md` and `docs/features/resume_structuring.md` (the AI step and the event stream).

**What it shows** (composed in `src/app/App.tsx`, which picks the page from the address: `#/` the form, `#/history` the past interviews, `#/history/{id}` one result; header links "New interview" and "Past interviews" switch between them, and Back, refresh and bookmarks work):
- **`InterviewForm`:**
  - Laid out as numbered cards: the CV (`CvDropzone`, step 1) beside Availability & pay (step 2) and Interviewer assessment (step 3), under an indigo title band. The seven required answers: notice period / start date, salary expectation (each at most 200 characters), work mode (Remote / Hybrid / On-site), rating (1–5), and strengths, concerns and overall notes (each at most 5,000 characters).
  - Work mode and rating are radio pills with nothing chosen at first, so the interviewer has to pick both. Strengths, concerns and overall notes show a live "used / 5,000" character count.
  - The browser enforces `required` and `maxLength`. Submit sends the whole form as multipart to `POST /api/resume_intake` through `api.ts`.
  - Before sending, the form also refuses what the browser lets through, and sends nothing:
    - a CV over 10 MB shows "The CV is larger than 10 MB." This is checked in the browser because the Vite dev proxy turns the backend's early 413 into a connection reset; the backend limit is still the real guard.
    - an answer of only spaces shows "Fill in <Label>." (for example "Fill in Strengths.") and focuses that field.
  - While sending, the button reads "Submitting…", the answers are locked (disabled fieldset), and a progress card covers the whole page (so it shows wherever the interviewer scrolled to). It has a bar, the three steps, and a `role="status"` line with the stage: "Submitting…" (until the backend's first event), "Extracting text…", then "AI cleaning…". Each stage stays on screen for at least 700 ms (`MIN_STAGE_MS`), because reading the text takes milliseconds and would otherwise flash by; an error stops that queue and shows at once. The backend streams the stages as Server-Sent Events; `api.ts` reads them with `fetch` (`EventSource` can only GET).
  - Errors go in a `role="alert"` element: a backend 413 shows "The CV is larger than 10 MB.", any other backend error (an HTTP error or an `error` event, e.g. a 422 "Couldn't find the candidate's name or email in the CV." or a 502 "AI extraction failed, please try again.") shows the backend's `detail` (or a generic "POST … failed with status N" when an HTTP error's `detail` isn't a string), and a network failure, or a stream that ends without a result, shows "Could not reach the server…".
- **`CvDropzone`:** the CV card: a dashed drop area with the native file input (`.pdf,.doc,.docx,.txt`, labelled "CV") stretched invisibly over it, so a click anywhere opens the picker and a drop lands on it. A dropped file is put into the input, so it is submitted like a picked one. Once a file is chosen the area shows its name, type and size. Under it, the accepted formats and limits. The area is highlighted while a file is dragged over it. Dropping several files at once is refused with the alert "Drop one CV at a time." and any CV already chosen is kept; the alert clears on the next single-file drop or file choice.
- **`IntakeResult`:** a title band ("Interview summary", saved time, intake id, then "Open branded PDF" (`BrandedPdfLink` from `resume_generation`, only when the intake has `structured_data`; it opens the branded MinistryHub PDF in a new tab) and "New interview"), then the candidate and extracted details (`StructuredResume` from `resume_structuring`, when the intake has `structured_data`) beside "Your assessment" (rating "3 / 5" with a bar, work mode, notice period, salary, and the three notes), the CV's file name and type, and the extracted text in a collapsible dark block with its line breaks kept. It moves keyboard focus to its "Interview summary" heading when shown, so focus doesn't fall back to the page body. "New interview" goes back to an empty form, with focus on the CV input.
- **`IntakeHistory`** (`#/history`): past interviews, newest first, 20 at a time with "Load more" (it asks for those older than the last row shown). Each row is one link to `#/history/{id}` showing an initials avatar, the candidate's name (the CV's file name for rows from before AI extraction), email, date and time, a violet "4 / 5" rating pill and a teal work-mode pill. Also "Loading…", "No interviews yet" with a link to the form, and an error with "Try again".
- **`IntakeDetail`** (`#/history/{id}`): shows `IntakeResult` for that intake. Right after a submit, App hands it the result it already has, so nothing is fetched again; otherwise it fetches `GET /api/resume_intake/{id}`. A 404 shows "This interview doesn't exist." with a link back to the list.

**Files:** `api.ts` (the `ResumeIntake`, `IntakeEvent`, `IntakeSummary` and `IntakeList` types, `listResumeIntakes(beforeId?)` and `getResumeIntake(id)` on `apiGet`, and `submitResumeIntake(form, onStage)`, built on `apiPostEventStream` in `src/shared/api/client.ts`; it resolves with the `done` event's result, throws `ApiError` for an `error` event, and throws a plain `Error` when the stream ends with neither), the three components, and `resumeIntake.css` (form layout, drop zone, progress card, the title band's buttons and result layout). The shared look (colour tokens, band, cards, buttons, fields, radio pills) is in `src/app/app.css`.

**Tests:**
- `CvDropzone.test.tsx` (Vitest): a drop of several files shows the alert, and choosing a file clears it.
- `InterviewForm.test.tsx` (Vitest, fetch stubbed with event-stream responses): work mode and rating start with nothing chosen and block the submit until chosen; the POST carries every answer and the `file` field; the "Submitting…" state and each stage; a `done` event split across two chunks after a `: ping` comment; a whitespace-only answer ("Fill in Strengths.", focused, no request); and the error messages (422 and 502 `error` events, a stream with only `reading`, HTTP 422 detail, HTTP 422 validation list, 413, network failure). jsdom can't put a real file into a file input, so the CV itself and the 10 MB check are covered by the e2e test.
- `IntakeHistory.test.tsx` (Vitest, fetch stubbed): rows with name, email, date, rating and work mode linking to `#/history/{id}`; the file-name fallback; "Load more" requests `before_id` and appends; the empty state; the error with "Try again".
- `IntakeDetail.test.tsx` (Vitest): uses the handed-over result without fetching; fetches when it has none; a 404 shows the not-found message and the link back.
- `IntakeResult.test.tsx` (Vitest): the answers, file name and type, one extracted-details section and the extracted text are shown; the heading takes focus; "New interview" calls the reset handler; "Open branded PDF" links to `/api/resume_generation/1` in a new tab (`rel` with `noopener`), and is absent when `structured_data` is null.
- `frontend/e2e/resume_intake.spec.ts` (Playwright):
  - **No live AI by default.** Unless `E2E_LIVE_AI=1`, a `beforeEach` aborts any upload a test doesn't answer itself, so no test reaches the backend's `POST /api/resume_intake`. The tests that submit answer the upload with a canned `text/event-stream` body (`route.fulfill`).
  - **Live test** (skipped unless `E2E_LIVE_AI=1`; run it only with the user's permission, since it makes 1 real OpenAI request and leaves one row in the dev database): drops a synthetic `.txt` CV with a name, email and one job, submits, sees the extracted name and email (90 s timeout), the Experience section, the CV text and the answers with focus on the heading, and "New interview" brings back an empty form with no radio checked.
  - Dropping two files shows the alert and keeps the CV already chosen; a single drop then clears it.
  - A PNG (415 event) and a text-less PDF (422 event) show the backend's message and keep the answers; an empty CV, notice period, work mode, rating or strengths blocks the submit and sends no request; a whitespace-only answer shows "Fill in Strengths.", focuses it and sends no request; double-clicking Submit sends one request.
  - A CV over 10 MB shows "The CV is larger than 10 MB." and sends no request.
  - At 375 px wide the page has no sideways scroll.
