# resume_generation

**Purpose:** render the branded MinistryHub resume as a PDF from the details AI extracted from a CV (`resume_structuring`, stored by `resume_intake`). The recruiter opens it from the result screen; it is rendered on demand and **not stored**. Design: [docs/features/resume_generation.md](../../../../docs/features/resume_generation.md).

## API
`GET /api/resume_generation/{intake_id}`: no body. Answers **200** with the PDF bytes:

| Header | Value |
|---|---|
| `Content-Type` | `application/pdf` |
| `Content-Disposition` | `inline; filename*=UTF-8''<"MinistryHub - {name}.pdf", percent-encoded>`. The name is AI output, so `quote(..., safe="")` encodes every special character, including `/`, `\`, quotes, CR and LF. There is no plain `filename=`. |
| `Cache-Control` | `no-store` (personal data: the browser keeps no copy) |

**Errors.** The body is `{"detail": "<message>"}` (the frontend's link opens it as plain JSON in the new tab).

| Code | When | `detail` |
|---|---|---|
| 404 | No intake with that id | "Intake not found." |
| 404 | The intake has no `structured_data` (rows from before AI extraction) | "This intake has no extracted details." |
| 422 | `intake_id` isn't an integer | FastAPI validation list |
| 500 | The stored `structured_data` doesn't validate as `ResumeData` (logged with the intake id only; the `ValidationError` quotes CV data, so it is never logged or chained) | "The stored CV details can't be read." |
| 500 | Chromium failed: not installed, crashed or timed out (`PdfRenderError`, cause logged) | "Could not create the PDF. Try again." |
| 503 | The database is unavailable | "The database is unavailable. Try again later." |

## Files
- `router.py`: the endpoint, a plain sync `def` (Playwright's sync API fails inside an `async def`; FastAPI runs a sync endpoint in a worker thread with no event loop). It reads the row through `resume_intake.service.get_resume_intake`, validates it as `ResumeData`, renders, and maps the errors above.
- `service.py`:
  - `build_resume_html(data, today)`: renders `templates/resume.html.j2` with Jinja2 (`autoescape=True`; `select_autoescape()` would not escape a `.j2` file). The template gets the `bullets` filter (`split_bullets`), the `http_url` and `current` tests (`is_http_url`, `is_current`) and the `format_duration` global, plus four values computed after `drop_blanks`: `experience` (`order_experience`), `phone` (`format_phone`), `link_groups` (`group_links`) and `skills` (the listed skills, then the inferred skills' names, unmarked).
  - `render_pdf(html)`: one headless Chromium per call (`sync_playwright`, `chromium.launch()`), JavaScript off, every routed request aborted (inline `data:` assets still load), `set_content`, a wait for `document.fonts.ready` (`page.pdf` doesn't wait for web fonts), then `page.pdf` at exactly 210 × 297 mm (Playwright's `format="A4"` is 8.27 × 11.7 in, about 1 pt taller) with `PDF_MARGIN`, `print_background=True` and the header/footer templates. Any `playwright.sync_api.Error` becomes `PdfRenderError`.
  - `HEADER_TEMPLATE` / `FOOTER_TEMPLATE`: the branding images as `data:` URIs at 100 % width, with Chromium's default 15 pt header/footer padding overridden so they reach the paper edge on every page. `PDF_MARGIN` (top 44 mm, bottom 23.8 mm, sides 13.2 mm) leaves room for them: the header is 35.6 mm tall and the footer 17.8 mm; top and sides were measured from the sample.
  - Dates: `read_date` reads a date as written into (year, month or None), with "Present", "current", "Till date" and the other ongoing words meaning today. `format_duration` gives a job's length ("10 mos", "1 yr", "11 yrs"; months counted inclusively, whole years from 12 months). `total_years` gives "WORK EXPERIENCE IN YEARS": the earliest readable start to the latest readable end, gaps included, floored to whole years; `None` hides the section. Both share `measure_span`.
  - Client feedback (2026-11-03, [docs/features/resume_upgrade.md](../../../../docs/features/resume_upgrade.md)), all at render time, so old rows get it without AI:
    - `is_current(entry)`: the end date holds an ongoing word (`ONGOING_WORDS`: "Present", "Current", "Till date"...). A current job's end chip always says "Present" (`chip-current`, yellow); with no start date only that chip shows.
    - `order_experience(jobs, today)`: one stable sort. Current jobs first (newest start first, an unreadable start after the dated ones), then past jobs by end date, newest first (the start date when the end can't be read; ties by start date), then jobs with no readable date, in CV order. A missing month counts as 13 for an end and 0 for a start. The AI's order isn't trusted.
    - `format_phone(phone)`: "(555) 010-0100" when the value has only digits, spaces and `( ) . + -` (`PHONE_CHARS`) and 10 digits, or 11 with a leading 1. A "+" counts as a country code, so it is formatted only as "+1" (11 digits), never e.g. "+45 12 34 56 78". Anything else (other countries, extensions, two numbers) is shown as written. PDF only: the stored data and the screen keep the CV's text.
    - `group_links(links)`: strips and de-duplicates, then groups by host (a host matches a domain when it is that domain or a subdomain of it). **Teaching & Worship Videos:** `VIDEO_HOSTS` (YouTube, youtu.be, Vimeo, fb.watch) and Facebook paths matching `FACEBOOK_VIDEO_PATH` (`/watch`, `/reel`, `/videos`, `/video.php`, `/share/v`, `/share/r`, `/<page>/videos`). **Social Media:** `SOCIAL_HOSTS` (LinkedIn, Facebook pages and profiles, Instagram, TikTok, X, Twitter, Threads). **Other Links:** everything else, including podcasts, sermon pages on church sites, bare words like "GitHub" and values `urlsplit` can't parse (it never raises). Returns `(label, links)` in `LINK_GROUPS` order, non-empty groups only.
  - `split_bullets` splits a description on CR/LF only, removing one leading marker (`•`, `-`, `*`, `·`, `–`, `▪`, `●`, `◦`, `➢`, Word's U+F0B7) only when whitespace follows it, so "-30%" stays as written. `drop_blanks` removes blank values, entries, pills and links (and strips links) before rendering. Entries may break across pages, with each title row kept with its first bullet; long unbroken words wrap. Ids above 2,147,483,647 are a 422. `is_http_url` mirrors the frontend's `linkOrText`.
- `templates/resume.html.j2`: the page: name, contact grid (email, formatted phone, current location), Professional Summary (the `summary` paragraph above "WORK EXPERIENCE IN YEARS"; shown when either exists), Experience & Education (Employment History in `order_experience` order; Education with one chip, the graduation date `end_date` only, "In progress" when ongoing, no chip for a start date alone, not sorted; Projects), Licenses & Certifications, Skills (listed then inferred, the same pills; no "AREAS OF GIFTING"), Additional Information (one block per link group, with its label and one line per link; Lucide icons `users`, `video` and `link`; only http(s) links are `<a>`). Empty sections and null fields are hidden. AI values go only into text nodes and quoted `href` attributes.
  - **Look (2026-11-03):** only MinistryHub's colours. Yellow `#ffc200` (confirmed from the header/footer PNG pixels) never carries text (about 1.6:1 on white): it is a 36 x 3 pt bar under the 24 pt navy name, a 4 pt block before each uppercase section title (11 pt, letter-spacing 0.08em), the rule after each subsection title, the current-role chip, the bullet markers and the summary's left border. Text is navy `#13293d` (the sample PDF's text colour; the PNGs themselves hold only white, yellow and black). Sections are separated by a light 0.75 pt `#e3e8ee` rule. Job titles are 10 pt; the company 8.5 pt, with the location muted after " · ". Icons are inline Lucide SVG paths.
- `templates/assets/`: `header.png` (1500 × 254) and `footer.png` (1500 × 127), cut once from page 2 of the client's sample PDF (no photo); `Inter-Regular/Medium/SemiBold.woff2` from the official Inter 4.1 release (static fonts: Chrome's PDF backend turns a variable font into Type 3 glyphs); `OFL.txt` (Inter's licence) and `LUCIDE-LICENSE.txt` (Lucide's ISC licence, plus the MIT notice for its Feather-derived icons such as `link`). Everything is inlined as `data:` URIs at import.

## Setup
`playwright` needs its browser once per machine, after `pip install`: `python -m playwright install --only-shell chromium` (the headless shell only, into `%LOCALAPPDATA%\ms-playwright`; no admin rights). Without it every request is a 500 and the log shows Playwright's "run playwright install" hint. A Docker image needs `playwright install --with-deps --only-shell chromium`.

## Data
No table and no column: the PDF isn't stored. It reads `resume_intakes.structured_data` through `get_resume_intake`. The `location` field it shows was added to `ResumeData` with this feature; migration `2349c371bb8a_add_location_to_structured_data.py` added `"location": null` to every stored object (a data migration, no schema change).

**Privacy:** the PDF is built in memory and returned; we write no files (Playwright creates and deletes Chromium's throwaway profile). Logs hold only the intake id, exception types and Playwright's messages, never CV text. The filename holds the candidate's name (user's choice). **Login and sequential ids:** the route needs a login (`auth.require_user`, attached in `app/main.py`); any logged-in user can open any intake's PDF by id (all recruiters see all interviews).

**Known limits (accepted):** one Chromium launch per PDF (about 1 s warm, 4 s cold); `page.pdf` has no timeout, so a hung Chromium holds one worker thread and one of the 2 render slots (`MAX_CONCURRENT_RENDERS`); a request waits at most `RENDER_WAIT_SECONDS` (120 s) for a slot, then gets the 500; the request's DB session stays open while rendering (uploads give their connection back after the spending-cap check, `ai_usage.require_ai_budget`); the branding images are ~180 dpi rasters; Inter is a look-alike of the paid TT Interphases; dates the parser can't read hide the duration.

- `test_service.py`: tables for `read_date`, `format_duration`, `total_years`, `split_bullets`, `is_current`, `order_experience` (current on top, past by end then start, a year-only end, a current job with no start, undatable last), `format_phone` (formatted and as-written cases) and `group_links` (every host rule, `fox.com` isn't `x.com`, "GitHub", `[::1` with no raise, group order, stripping, duplicates, `[]`); `build_resume_html` escaping (the summary too), http-only links under the group labels and no "LINK 1", hidden empty sections, every section with full data, the summary above the years and the section hidden with neither, "Present" for a job written "Current" (alone when there is no start), ordered jobs and the formatted phone, the education chip (graduation date, "Expected 2026", "In progress", none for a start date alone), inferred skills after the listed ones, an old-shape row, and no external URLs (every asset is `data:`); a Playwright error becomes `PdfRenderError`. **One real render** (user-approved; needs the Chromium shell, and fails rather than skips without it): 12 synthetic jobs make 2+ A4 pages, each with the header and footer images, "Jane Doe", the long current job (listed last, ordered first) and "Present" on page 1, and only Inter fonts embedded.
